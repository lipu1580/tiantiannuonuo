## 2. P0：最终演奏模式必须完成

### F-01 5 路压电触发链路

#### 现状

- 没有 `piezo_peak.sv` 或等效模块。
- `input_top` 没有压电相关端口。
- 没有压电峰值读取、阈值、力度映射、自动 NOTE_OFF。
- 没有峰值保持电容的放电控制。

#### 目标

5 片压电片各自独立完成：

```text
压电片 → 保护/峰值保持 → ADS7830 CH2~CH6
      → 峰值读取 → 阈值判断 → NOTE_ON + velocity
      → 防重复触发 → 自动 NOTE_OFF
      → 峰值电容放电 → 重新武装
```

#### 缺失内容

1. **峰值读取**：从 `sample_valid/sample_channel/sample_data` 中取出属于本路的峰值。
2. **阈值**：每路独立阈值，低于阈值不触发。
3. **力度映射**：峰值 → 1~255，支持每路增益/偏移校准。
4. **防重复触发**：一次拨动只产生一个 NOTE_ON，建议 30~80 ms。
5. **自动 NOTE_OFF**：压电片没有可靠松开信号，触发后 300~800 ms 自动释放。
6. **音符锁存**：触发瞬间锁存 `note_id`，自动 NOTE_OFF 使用同一个编号。
7. **峰值放电**：`peak_rst[4:0]` 控制 5 路 2N7002，读完峰值后放电。
8. **事件仲裁**：与 ALL_NOTES_OFF、其他压电事件共用 `event_queue`。

#### 建议接口

```systemverilog
module piezo_peak #(
    parameter integer PIEZO_COUNT      = 5,
    parameter integer NOTE_W           = 7,
    parameter logic [7:0] THRESHOLD    = 8'd20,
    parameter integer RETRIGGER_MS     = 50,
    parameter integer NOTE_OFF_MS      = 500
)(
    input  logic        sys_clk,
    input  logic        rst_n,

    input  logic        sample_valid,
    input  logic [2:0]  sample_channel,
    input  logic [7:0]  sample_data,
    input  logic [2:0]  piezo_ch_base,     // 第一路压电的 ADC 通道
    input  logic [6:0]  base_note,
    input  logic signed [3:0] octave_offset,

    output logic [4:0]  peak_rst,          // 峰值电容放电

    output logic        event_req_valid,
    input  logic        event_req_ready,
    output logic [1:0]  event_req_type,
    output logic [6:0]  event_req_note,
    output logic [7:0]  event_req_velocity,

    output logic [4:0]  hit_debug,
    output logic [4:0]  active_debug
);
```

#### 验收标准

- [ ] 5 路独立触发，互不串扰
- [ ] 轻/中/重击 velocity 明显不同
- [ ] 一次拨动只产生一个 NOTE_ON
- [ ] 自动 NOTE_OFF 时间可参数化，不会长鸣
- [ ] 峰值电容能正确放电，连续触发不累积
- [ ] 压电触发到 NOTE_ON 的延迟 <2 ms
- [ ] 5 路同时触发时不丢事件

#### 依赖/风险

- 依赖硬件峰值保持电路和 `peak_rst` 接线。
- 压电片安装位置会影响串扰和灵敏度，需要机械调试。
- 8 位 ADC 的力度分辨率有限，但足够做相对力度。

### F-02 7 通道 ADC 调度

#### 现状

`input_top.sv` 中 `next_adc_ch` 只在两个通道之间翻转：

```text
FSR (CH0) → 电位器 (CH1) → FSR → ...
```

#### 目标

7 通道轮询：

| 通道 | 用途 |
|---|---|
| CH0 | FSR |
| CH1 | 电位器 |
| CH2 | 压电 P0 |
| CH3 | 压电 P1 |
| CH4 | 压电 P2 |
| CH5 | 压电 P3 |
| CH6 | 压电 P4 |
| CH7 | 备用 |

#### 缺失内容

1. 把 `next_adc_ch` 的两通道翻转改成 0~6 循环计数器（或通道 ROM）。
2. `SAMPLE_INTERVAL` 从 250 us 降到 20~50 us，保证一轮扫描 <1.5 ms。
3. 每个通道的样本要带通道号，供 `fsr_filter`、`expression_mapper`、`piezo_peak` 分流。
4. 处理 `adc_bus_error` 时的调度：出错后跳过该通道，继续下一轮。

#### 验收标准

- [ ] 7 通道按固定顺序轮询
- [ ] 一轮扫描 <1.5 ms
- [ ] 每个通道的样本不会串到别的模块
- [ ] 单通道故障不会永久阻塞整个调度
- [ ] 仿真能抓到完整一轮 7 通道数据

### F-03 矩阵配置模式

#### 现状

- `note_map.sv` 把 K0~K11 映射为 MIDI 60~71。
- `key_event_decoder.sv` 在按键按下时直接发 `NOTE_ON`。
- 矩阵目前是“音符键盘”，不是“选音区/音色”的配置输入。

#### 目标

最终方案：

| 键 | 功能 |
|---|---|
| K0~K11 | 选择根音 C4~B4（更新 `base_note`，不发声） |
| K12 | ALL_NOTES_OFF |
| K13 | 八度 +1 |
| K14 | 波形切换 |
| K15 | 八度 -1 |

#### 缺失内容

1. 新增 `base_note` 寄存器（7 位）。
2. `note_map` 对 K0~K11 输出根音，而不是直接产生 NOTE_ON。
3. `key_event_decoder` 或新的 `matrix_config_decoder` 只更新配置，不发音符事件。
4. 增加 `MATRIX_MODE` 参数：
   - `0` = 当前“矩阵当键盘”的测试模式；
   - `1` = 最终“矩阵选音区”的演奏模式。
5. 音区/八度改变只影响之后新触发的音符，已发声音符保持原音高。

#### 验收标准

- [ ] `MATRIX_MODE=1` 时 K0~K11 不产生 NOTE_ON
- [ ] `base_note` 正确更新
- [ ] 八度 ±1 正确影响后续压电触发音符
- [ ] K12 仍能发 ALL_NOTES_OFF
- [ ] `MATRIX_MODE=0` 时原有按键弹音测试仍通过

### F-04 压电音符映射

#### 现状

没有压电音符映射。

#### 目标

5 片压电按大调五声音阶：

| 压电片 | 偏移 | 根音 C4 时 |
|---|---|---|
| P0 | +0 | C4 (60) |
| P1 | +2 | D4 (62) |
| P2 | +4 | E4 (64) |
| P3 | +7 | G4 (67) |
| P4 | +9 | A4 (69) |

```text
note_id = clamp(base_note + PIEZO_OFFSET[i] + 12 * octave_offset, 0, 127)
```

#### 缺失内容

1. `PIEZO_OFFSET[5]` 常数表。
2. 触发瞬间锁存 `note_id`。
3. 自动 NOTE_OFF 使用锁存的 `note_id`。
4. 八度切换不影响已触发但未释放的音符。

#### 验收标准

- [ ] 根音 C4、八度 0 时，P0~P4 分别发出 60/62/64/67/69
- [ ] 八度 +1 后新触发音符 +12
- [ ] 八度切换时已发声音符不被改音高
- [ ] note_id 不会超出 0~127

### F-05 FSR/压电角色分离

#### 现状

`input_top.sv` 中：

```systemverilog
assign note_velocity = pressure_valid ? fsr_velocity : `DEFAULT_VELOCITY;
```

FSR 同时充当：

- 矩阵按键按下瞬间的 `event_velocity`；
- 持续 `expression`。

#### 目标

最终方案：

| 信号 | 来源 |
|---|---|
| `event_velocity` | 压电峰值 |
| `expression` | FSR 持续压力 |

FSR 不再参与矩阵按键力度。

#### 缺失内容

1. 删除/条件化 `note_velocity` 的 FSR 来源（仅保留 `MATRIX_MODE=0` 测试模式）。
2. `expression` 映射增加下限，例如 `EXPR_MIN=64`，避免松开 FSR 后完全无声。
3. 明确 FSR 是全局表情，作用于所有活跃声部。
4. 可选：FSR 零点/满量程校准。

#### 验收标准

- [ ] 压电触发时 velocity 来自压电峰值，不受 FSR 影响
- [ ] FSR 只改变 `expression`
- [ ] FSR 松开时声音不会突然完全消失（可配置）
- [ ] `MATRIX_MODE=0` 时旧测试仍可使用 FSR 力度

## 3. P1：可靠性与演奏质量

### F-06 电位器中心死区

#### 现状

`expression_mapper.sv` 线性映射：

```text
pitch_bend = clamp(2048 + (pot - 128) * 16, 0, 4095)
```

没有死区。

#### 目标

在中心附近加死区：

```text
|pot - 128| <= DEADZONE  -> pitch_bend = 2048
否则线性映射
```

建议 `DEADZONE = 4` LSB（对应 ±64 pitch 单位）。

#### 缺失内容

1. 参数 `CENTER_DEADZONE`。
2. 死区判断和映射。
3. 仿真覆盖中心、边界、两端。

#### 验收标准

- [ ] 电位器静止时 `pitch_bend` 稳定在 2048
- [ ] 死区外仍能平滑滑音
- [ ] 两端能到 0/4095

### F-07 ADC 总线超时/恢复

#### 现状

`adc_ads7830.sv` 状态机没有超时机制。  
如果 SDA 被从机拉死、SCL 异常或状态机跑飞，可能一直停在某个状态。

#### 目标

1. 每次事务加超时计数器（例如 10 ms）。
2. 超时后：
   - 置 `bus_error`；
   - 强制回到 IDLE；
   - 可选：发 9 个 SCL 脉冲 + STOP 做总线恢复。
3. 下一次 `sample_req` 能重新开始。

#### 缺失内容

1. `timeout_cnt` 和超时阈值。
2. 超时状态转移。
3. 总线恢复序列（可选）。
4. testbench 模拟 SDA 被拉死。

#### 验收标准

- [ ] SDA 卡死时不会永久阻塞
- [ ] `bus_error` 正确置位
- [ ] 超时后下一次采样能恢复
- [ ] 正常事务不受影响

### F-08 FSR 零点/满量程校准

#### 现状

`fsr_filter.sv` 只有固定 `NOISE_GATE` 和线性映射，没有零点/满量程校准。

#### 目标

支持：

```text
raw_min / raw_max -> 映射到 0~255
```

可以在上电时自动采集零点，或通过参数/配置总线设置。

#### 缺失内容

1. `RAW_MIN`、`RAW_MAX` 参数或寄存器。
2. 零点自动校准状态（可选）。
3. 校准后的映射和限幅。
4. 仿真覆盖不同分压电阻/FSR 个体差异。

#### 验收标准

- [ ] 不按压时稳定输出 0
- [ ] 重压时能到 255 附近
- [ ] 不同 FSR 个体差异可通过校准补偿
- [ ] 校准不影响快速起音

### F-09 事件 FIFO 溢出清除/同键覆盖

#### 现状

- `input_top.sv` 中 `overflow_clear` 接 `1'b0`，溢出后只能复位清除。
- 每个按键只有一个 pending 槽位；极端背压下，同键的快速按放可能覆盖前一个事件。

#### 目标

1. 提供系统级 `overflow_clear`（按键、配置寄存器或 test_mode 切换时清除）。
2. 评估是否需要每键 2 个历史槽位，或明确“FIFO 满时允许丢事件并置 overflow”的策略。
3. 在文档和调试信号中明确溢出行为。

#### 缺失内容

1. `input_top` 的 `overflow_clear` 输入或自动清除逻辑。
2. 可选的每键多事件历史。
3. 溢出场景的仿真。

#### 验收标准

- [ ] 溢出后可通过确定方式清除
- [ ] 不静默覆盖已入队事件
- [ ] 溢出时 `input_overflow` 可观测

### F-10 矩阵鬼键防护

#### 现状

4×4 矩阵只适合单键或有限和弦。多个键同时按下时可能出现鬼键。

#### 目标

1. 明确支持范围（例如“最多 4 键且不出现 L 形组合”）。
2. 可选：每个按键串 1N4148 实现全键无冲。
3. 或在软件层限制同时按键组合。

#### 缺失内容

1. 文档已说明限制，但代码没有检测/限制。
2. 可选硬件二极管方案未实施。
3. 仿真没有鬼键场景。

#### 验收标准

- [ ] 文档明确支持范围
- [ ] 演示时不会出现意外音符
- [ ] 若做全键无冲，硬件/逻辑方案验证通过
